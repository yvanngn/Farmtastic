# Règles pour Claude — Farmwest (moteur Ferme)

## Farmwest (depuis le 17/11/2026)
- Le jeu s'appelle **Farmwest** (ancien nom : Farm'tastic), thème **Far West**. Dépôt `yvanngn/farmwest`, GitHub Pages https://yvanngn.github.io/farmwest/, jeu claude.ai toujours republié sur la même page.
- **Feuille de route : `docs/ROADMAP.md`**. On fait **un lot à la fois**, dans l'ordre, sur demande ; poser d'abord les questions ❓ du lot. En fin de lot : cocher la roadmap, compléter le carnet, et tenir à jour le manuel du joueur (`docs/MANUEL.md`) et la liste de complétion (`docs/COMPLETION.md`).
- Carte de référence de la région et du style graphique visé : `docs/carte-region-farmwest.jpg`.
- **Personnages (état du 20/11)** : les habitants qui ont une planche fournie sont affichés d'après elle (`look.planche` → `SHEETS` dans `src/render/sheets.js`, dessin par `drawNpcPlanche`) : Manu, Luna, Hailey, Harry, Remy, Myst, Ed, Igor, Jade, Suzie (planches « v2 »), et le héros / l'héroïne (`hero_*`, cheveux recolorables). Franck, Rouky et Golgolas restent en « pixel moderne » (`folk.js`). Toutes les planches sont **préchargées au démarrage** (`preloadSheets`, dans main.js) et le **profil droit est un miroir préparé une fois** par planche (`mirrored`) : ne pas retourner les images à chaque frame. `sheets.js` ne garde que les planches utilisées (test `tests/sheets.test.js`) ; une planche abandonnée doit en être retirée.
- **Personnages (choix du 18/11 au soir) : style « pixel moderne », `src/render/folk.js`** (validé sur maquette d'après `docs/personnages-reference.jpg`). Chaque personnage est décrit dans `CAST` (silhouette `stout`/`muscle`/`kid`/`f`/`thin`, coiffure `messy`/`spiky`/`short`/`bun`/`braid`/`pigtails`/`long`, chapeau `cowboy`/`cap`/`flat`/`bowler`/`toque`/`band`, `beard`/`mustache`, vêtements dans `garments` : `overalls`, `coat`, `jacket`, `vest`, `lapels`, `fur`, `apron`, `suspenders`, `backpack`, `belt`, `toolbelt`, `hoodie`, `chef`, `scarf`, `bolo`, `stetho`, `towel`, `pocket`, `pipe` ; couleurs dans `mats`, motifs `plaid`/`check`/`knit`/`flowers`/`stripe`). Un habitant pointe vers sa description par `look.folk` (src/data/npcs.js) ; le héros est traduit depuis sa personnalisation (`heroSpec`). Image 32 × 64 (affichée à 0,75), 4 tons, contour teinté ; vues face, dos, profil (gauche = miroir), marche en 4 temps ; calculée une fois puis gardée en cache. Changer une tenue = changer une ligne de `CAST`. Avant (remplacé) : la poupée `src/render/paperdoll.js` (reste le dessin de secours).
- (Avant le 18/11, remplacé :) **on partait des planches de sprites fournies par l'utilisateur** (plus de Gemini). Chaque planche est déposée dans `docs/sprites/<nom>.png` et passée par `python3 -I tools/sprite-from-planche.py` (ajouter le personnage dans `PLANCHES` : taille du pixel d'origine `PX`, hauteur dans le monde `H`, poses de face / dos / profil, miroirs). **Qualité gardée telle quelle** : grille d'origine retrouvée, toutes les couleurs et le contour d'origine, seul le fond devient transparent ; le jeu l'affiche à `H` pixels du monde (champs `sw`/`sh` dans `sheets.js`), donc tout le détail se voit à l'écran. Ne pas réduire, ni réduire les couleurs, ni recontourer une planche fournie. Les anciens outils (`sprite-from-sheets.py`, `sprite-from-reference.py`) ne touchent plus à ces personnages.
- Ancienne règle (personnages pas encore refaits) : **planche de référence `docs/personnages-reference.jpg`** (tous les personnages, de face, de profil et de dos). Tout nouveau personnage garde cet esprit : petit sprite 16 × 31 « façon Stardew », tête 8 × 10, yeux avec du blanc, 3 tons par couleur (lumière en haut à gauche), contour coloré (jamais noir), tenue lisible en une silhouette (chapeau, manteau, salopette…). Depuis la v0.1.36, chaque personnage est affiché depuis sa **planche de sprites** (`assets/sprites/<nom>.png`, `sheet:` dans son `look`), générée par `python3 tools/sprite-from-sheets.py` depuis les planches de marche fournies par l'utilisateur (`docs/sprites/*.jpg`, prioritaires) ou, à défaut, depuis la planche de référence (`python3 tools/sprite-from-reference.py`, à lancer avant) ; cadres des cellules à indiquer dans le script pour un nouveau personnage ; le dessin par code (`rawChar`, `src/render/sprites.js`) reste le secours et sert au héros personnalisé.
- Ne pas renommer la clé de sauvegarde (`ferme_save_v1`) ni le préfixe Supabase (`ferme_`) : les parties existantes seraient perdues.

- Lire ce fichier et README.md avant tout ; ils font foi.
- `src/systems/` ne touche JAMAIS le DOM ni `Math.random`/`Date.now` directement : utiliser `g.bus.emit`, `g.rnd()`, `g.now()`.
- Tout ce qui persiste vit dans `g.S` (sérialisable JSON). L'éphémère (ennemis, autres joueurs, fx) vit hors de `S`.
- Nouveau champ dans `S` → valeur par défaut dans `defaultState()` (la migration complète les vieilles sauvegardes). Changement incompatible → incrémenter `CFG.VERSION` et migrer dans `migrate()`.
- Réseau : jamais d'écriture base à chaque frame. Positions = Broadcast (≤ 10 Hz, seulement si changement). Identité = Presence. Base = sauvegarde (30 s) et objets partagés.
- Rendu : sol statique pré-rendu, culling des tuiles visibles, HUD ≤ 4×/s.
- Toute fonctionnalité ou correction = un test dans le fichier du système concerné. Lancer uniquement ce fichier.

## Équilibrage (règle de l'utilisateur, 20/11)
- Compte rendu d'équilibrage **seulement quand l'utilisateur le demande** (skill « compte-rendu-equilibrage ») : `node tools/equilibrage.mjs [jours] [graines]` (ou `npm run equilibrage`) lance le moteur `tools/simulate.mjs` pour 3 profils (tranquille, moyen, acharné) × 3 parties, écrit les constats chiffrés dans `docs/EQUILIBRAGE.md` et l'historique dans `docs/equilibrage/<date>.json`. Claude complète la partie « Analyse et recommandations ». Ne jamais changer une valeur du jeu sans l'accord de l'utilisateur.
- Quand un système du jeu change (prix, XP, énergie, nouvelle activité), mettre à jour `tools/simulate.mjs` s'il le concerne, pour que la simulation reste fidèle.

## Dialogues (règle de l'utilisateur)
- Toutes les répliques des PNJ sont dans `src/data/npcs.js`. `node tools/export-dialogues.mjs` écrit `docs/DIALOGUES.md` avec 🆕 sur les répliques non validées et affiche leur nombre.
- Le document reprend aussi (20/11) : toutes les autres répliques des PNJ (quêtes : étal de Suzie, chaudron de Remy…, repérées automatiquement), les titres et étapes des quêtes (`src/systems/quests.js`), le courrier (`mail.js`, `golgolas.js`), les conseils de tuto (`tip(g, 'id', '…')`) et les messages à l'écran à texte fixe (`emit('toast', '…')`). Écrire ces textes en chaîne simple (sans `${}`) pour qu'ils soient repris ; ne jamais mettre 🆕 dans le texte du jeu.
- **Dès 100 répliques 🆕**, envoyer `docs/DIALOGUES.md` à l'utilisateur pour relecture. Ses corrections s'appliquent telles quelles, puis `node tools/export-dialogues.mjs --valider` et committer `tools/dialogues_valides.txt`.
- Discussions comme dans Witch'rok : la réplique du jour reste en tête, puis le choix des sujets du PNJ (`topics`) et « Rien. ».
- Mémoire du projet : `docs/CARNET.md` (le lire en début de séance, le compléter à la fin).
- `index.html` (GitHub Pages) est **généré** depuis `play.html` (claude.ai) : après toute modification de `play.html`, lancer `node tools/build-index.mjs` (un test vérifie qu'ils sont synchronisés).

## Versions (règle de l'utilisateur)
- Semver horodaté dans `src/version.js`, affiché sur l'écran titre et dans ⚙ Réglages ; historique dans `docs/VERSIONS.md`.
- **À chaque publication** : `node tools/version.mjs "courte note"` (patch +1, date et heure de Paris), puis `node tools/build-index.mjs`, publier, committer.
- **Mineure / majeure : jamais de moi-même**, seulement quand l'utilisateur le demande (`node tools/version.mjs minor` / `major`).
